# Accepted-profile evidence

These are raw records from the historical accepted paired INT8 trial, its numerical gates, and the latest EXP101 control/candidate comparison. They do not by themselves prove that a newly compiled installer reproduces the deployment. Fresh source-build/install validation is recorded separately before release.

`accepted-benchmark260k.json`: thinking-enabled, 259,944 fresh tokens, zero reuse, 1,024 output allowance. `accepted-quality128k.json`: randomized marker retrieval. `accepted-engine-stage-timing.txt`: stage timings. `supervisor-*.log`: frozen kernel numerical and memory checks. EXP101 files document no accepted improvement from later page-four specialization. Logs may contain historical build paths; no model weights, credentials, operator service units or private configuration are included.


The release-validation directory contains clean-build device-code proof, CPU tests and guarded numerical checks. Gate log timings are incidental, not full-model performance claims. The installer receipt, fresh-install benchmark/quality and forced-failure rollback/restoration receipts distinguish actual end-to-end acceptance from mocked tests. Local GGUF bytes were reused and independently hashed; a fresh operating-system bootstrap and network redownload were not tested.
